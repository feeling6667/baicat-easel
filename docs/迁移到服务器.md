# 把工作台搬到 Ubuntu 服务器（2核 2G · 国内机房）





> 定稿：2026-10-21 · 适用：Easel v0.3.0 + openclaw + **magpie Linux CLI 版**  
> 环境：Ubuntu 22.04 · 2 核 2G · 40G · 3Mbps · 国内机房  
> 范围：**只搬"生产大脑"**。浏览器登录、一键发布、剪视频**不上服务器**（原因见文末）。

---

## 0. 一句话方案

服务器上跑 **工作台网页（7860）+ openclaw 网关（18789）+ magpie 模型网关（3425）**，  
你在自己电脑上通过 **SSH 隧道**打开网页用。生成的内容传回本机，发布和剪视频仍然在本机做。

```
你的电脑 ──SSH 隧道──▶ 服务器 127.0.0.1:7860（工作台）
   │                        ├── openclaw 网关（agent 干活）
   └── 产物文件（scp 回传）   └── magpie 网关 :3425 ──▶ 各家模型 API
```

> 为什么服务器上也要装 magpie：你的 `openclaw.json` 里模型地址写的就是  
> `http://127.0.0.1:3425/v1`。magpie 在服务器上跑起来，**配置文件原样搬过去即可，不用改模型与 key**。

**为什么这样够用**：砍掉浏览器和视频后，服务器常驻内存 ≈ 1.0–1.5G（本机实测 openclaw 694M +  
Easel web 187M + magpie 317M + 系统 200M），2G 靠 swap 兜底，够跑生图/加字。

## 1. 三个必须在搬之前处理掉的坑

### 坑 1：前端构建产物不在仓库里

`dist/` 被 `.gitignore` 排除（第 7 行）。**只 `git clone` 拿到的是没有界面的仓库**，  
网页会回落到 `web/static/index.html` 那个旧版界面。  
→ 要么把本机的 `web/frontend/dist/`（648K）一起传上去，要么在服务器上 `npm i && npm run build`  
（需要 88M 的 node_modules）。**本方案选前者**。

### 坑 2：模型配置不在仓库里（**服务器上装 magpie 就不用改它**）

`~/.openclaw-easel/openclaw.json` 是你手改过的，不在仓库、`setup.sh` 也不会生成。  
里面 magpie 的地址是 `http://127.0.0.1:3425/v1` —— 只要服务器上也跑着 magpie，  
**这个文件原样复制过去就能用，一个字都不用改**。要带的是两样东西：

| 文件                                                        | 说明                                 |
| --------------------------------------------------------- | ---------------------------------- |
| `~/.openclaw-easel/openclaw.json`                         | 网关配置（模型清单、http 端点开关等）              |
| `~/.config/magpie/{providers,settings}.json` + `routing/` | magpie 的供应商与密钥（**实测是明文存的，直接复制可用**） |

> 只带 `agents.defaults.model.primary` 指向的那个模型还在就行。当前 .env 里  
> `EASEL_AGENT_MODEL=cline/cline-pass/deepseek-v4.1-flash`，对应 providers 里的  
> `clinepass`（ClinePass）——把 `providers.json` 带过去，这个模型名在服务器上一样成立。  
> ⚠️ **订阅类登录（Claude Pro / ChatGPT Plus / Copilot）会失效**：它们是走浏览器 OAuth 的，  
> 换机器要重新授权。服务器上只用 **API key 型**的 provider（基元 tokenrhythm、ClinePass、x5m5x5）。

### 坑 3：Python 依赖很重，弱网会装很久

`pyproject.toml` 里含 opencv / pandas / matplotlib / librosa / **faster-whisper** /  
**rembg（onnxruntime）** / biliup / edge-tts / playwright，pip 下载约 600M–1G。  
`setup.sh` 会自动切清华源，但 3Mbps 下**仍可能要 40–60 分钟**，别以为卡住了。

## 2. 服务器侧（Ubuntu，root 或 sudo 用户）

### 2.1 加 swap（**必做，2G 内存的保命线**）

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h   # 确认 Swap 有 2.0Gi
```

### 2.2 系统依赖

```bash
sudo apt update
sudo apt install -y git python3-venv python3-pip ffmpeg fonts-noto-cjk build-essential
python3 -V          # 22.04 是 3.10，24.04 是 3.12，都够（要求 ≥3.10）
```

### 2.3 放代码

```bash
mkdir -p ~/apps && cd ~/apps
# 方式 A：本机打包 scp 上来（推荐，能带上 dist 和 assets）
#   本机执行见 §3
tar xzf easel-upload.tar.gz
cd Easel
```

### 2.4 一键安装

```bash
bash setup.sh --openclaw      # 自动装 Node 24（阿里云镜像）+ openclaw + venv + 依赖
```

> - Chromium 那步失败**只告警不中断**，不用管——我们不发布，不需要它。
> - 如果结尾弹出交互提问（"现在配置模型 / 填 API key？"）**一律跳过**：配置我们稍后  
>   直接把现成的 `.env` 和 openclaw.json 放进去（§2.6），不用手填。
> - pip 装依赖那一段会跑很久（40–60 分钟），看日志有在动就别中断。

### 2.5 装 magpie（**无头 CLI 版**，别装 GUI 版）

官方 Linux 有两套资产，别装错：

| 资产                       | 说明                                    | 服务器上要不要   |
| ------------------------ | ------------------------------------- | --------- |
| `magpie-linux-amd64`     | 桌面版，**要 GTK 3 + WebKitGTK 4.1**，得插显示器 | ❌ 不要      |
| `magpie-cli-linux-amd64` | **纯终端版**，只跑网关                         | ✅ **要这个** |

```bash
curl -fsSL https://usemagpie.ai/install.sh | sh     # 自动识别 linux-amd64
magpie help | head -20                              # 能打出命令 = 装好了
magpie --version
```

只跑网关、不开窗口，先前台验证：

```bash
magpie serve
# 另开一个终端：
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3425/v1/models   # 有响应就行
```

验证通过后改成常驻（**magpie 自带 systemd 注册，开机自启、无窗口**）：

```bash
magpie daemon install
magpie daemon status
```

> ⚠️ 如果 `daemon install` 装的是 **user unit**（`~/.config/systemd/user/`），服务器没人登录时  
> 不会自动起。补一条让它开机就跑：
>
> ```bash
> loginctl enable-linger $USER
> ```

> 为什么不用 GUI 版：GUI 要 GTK3 + WebKitGTK 4.1 + 显示器，还要多喂一个 WebKit 进程；  
> 2G 内存经不起。CLI 版只有网关本体，够用。
>
> **如果 `install.sh` 在 22.04 上因为缺 GUI 依赖报错**：别去装 GTK/WebKitGTK，  
> 直接从 [releases 页](https://github.com/yetone/magpie-releases/releases/latest) 下  
> `magpie-cli-linux-amd64`，手动放到 `~/.local/bin/magpie` 并 `chmod +x`：
>
> ```bash
> mkdir -p ~/.local/bin
> curl -fL -o ~/.local/bin/magpie \
>   https://github.com/yetone/magpie-releases/releases/latest/download/magpie-cli-linux-amd64
> chmod +x ~/.local/bin/magpie
> echo 'export PATH=$HOME/.local/bin:$PATH' >> ~/.bashrc
> ~/.local/bin/magpie --version
> ```

### 2.6 放配置（3 份东西，都不在仓库里）

```bash
# 1) Easel 的 .env（密钥 / 模型名）
cp ~/apps/.env ~/apps/Easel/.env && chmod 600 ~/apps/Easel/.env

# 2) openclaw 网关配置 —— 原样放，baseUrl 还是 127.0.0.1:3425，因为 magpie 就装在旁边
mkdir -p ~/.openclaw-easel
cp ~/apps/openclaw.json ~/.openclaw-easel/openclaw.json

# 3) magpie 的供应商与密钥（只带 3 样，别整目录拷）
mkdir -p ~/.config/magpie/routing
cp ~/apps/magpie/providers.json ~/.config/magpie/providers.json
cp ~/apps/magpie/settings.json  ~/.config/magpie/settings.json   # 没有就跳过
cp ~/apps/magpie/routing/*      ~/.config/magpie/routing/ 2>/dev/null || true

# 验证 magpie 认得这些 key
magpie providers        # 应列出 基元/ClinePass/x5m5x5 等，key 显示为掩码
```

> **不要整目录拷 `~/.config/magpie/`**：里面 `install-id`、`logins.json`、`plugin-auth.json`  
> 是跟本机/浏览器授权绑的，带过去只会添乱（尤其是 `logins.json` 里的订阅登录，换机器必然失效）。  
> 只要 `providers.json`（**明文存 key，实测可直读**）+ `settings.json` + `routing/` 就够。

### 2.7 起服务（systemd，开机自启 + 崩了自动拉起）

```bash
# 顺序很重要：先把 magpie 起好，再起 easel（easel 启动时会去连 127.0.0.1:3425）
magpie daemon status || magpie daemon install
cd ~/apps/Easel && .venv/bin/easel gateway start && .venv/bin/easel web
# 能访问 http://127.0.0.1:7860 后 Ctrl+C，再配下面的 systemd
```

`/etc/systemd/system/easel.service`（把 `<用户名>` 换成你的；`<UID>` 用 `id -u` 查）：

```ini
[Unit]
Description=Easel workbench (gateway + web)
After=network-online.target
Wants=network-online.target
# 如果你的 magpie 服务单元确实叫 magpie.service（systemctl list-units | grep -i magpie 确认），
# 把下面两行的注释去掉，保证 easel 一定在 magpie 之后起
# After=magpie.service
# Requires=magpie.service

[Service]
Type=simple
User=<你的用户名>
WorkingDirectory=/home/<你的用户名>/apps/Easel
Environment=PATH=/home/<你的用户名>/apps/Easel/.venv/bin:/usr/local/bin:/usr/bin:/bin
# 一条命令把两个进程拉起来：先后台起网关，等它就绪，再把主进程换成 web
ExecStart=/bin/bash -lc 'cd /home/<你的用户名>/apps/Easel && .venv/bin/easel gateway start & sleep 10; exec .venv/bin/easel web'
Restart=always
RestartSec=5
KillMode=control-group

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now easel
sudo systemctl status easel --no-pager
sudo journalctl -u easel -n 50 --no-pager
```

> 为什么不用 `ExecStartPost`：systemd 会把 `ExecStartPost` 当成"启动完成前的收尾命令"，  
> 而 `easel web` 是常驻不退出的——写在那里服务会永远卡在 activating。用 `bash -c '… & … exec'`  
> 让网关在后台、web 当主进程，`KillMode=control-group` 保证停服务时两个一起停。

### 2.8 防火墙：**只开 SSH，7860 绝不开**

```bash
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status        # 不要出现 7860
```

```bash
# 每次要用，先在自己电脑上开隧道（窗口别关）
ssh -L 7860:127.0.0.1:7860 root@<服务器IP>
# 然后浏览器打开
```

**手机/平板也想看**（可选）：装 Caddy 做反代 + 密码，并给 Easel 加白名单：

```bash
# .env 里加
EASEL_EXTRA_HOSTS=work.example.com
EASEL_EXTRA_ORIGINS=https://work.example.com
```

```caddyfile
work.example.com {
    basic_auth {
        yuan <用 caddy hash-password 生成的密码哈希>
    }
    reverse_proxy 127.0.0.1:7860
}
```

> 注意 Easel **本身没有登录**（`web/app.py` 绑 0.0.0.0 且无鉴权），密码这道门必须由  
> Caddy/Nginx 站在前面，不能指望 Easel 自己拦。

## 8. 想"双击就能用"：三种封装方式

先把问题拆开：**"封装成软件"真正要解决的只有两件事** ——
① 不用手敲 SSH 命令；② 看起来像个独立程序（有图标、独立窗口、不露地址栏）。
至于登录鉴权、多端同步，那不是壳能解决的。

| 方式 | 做法 | 工作量 | 实际体验 | 结论 |
|---|---|---|---|---|
| **A · 启动器 + 应用窗口** | 一个 `.lnk` / `.ps1`：后台建 SSH 隧道 → 等端口通 → 用应用窗口打开 | 半天 | 双击出独立窗口，任务栏有自己的图标，没有地址栏 —— 看着就是软件 | ✅ **先做这个** |
| **B · 真安装包（壳）** | Electron / Tauri / WebView2 包一个 `.exe`：自带隧道 + 内嵌页面 + 托盘 + 开机自启 | 2–3 天 | 和 A 视觉上几乎一样，多了安装流程和一个 50–150MB 的壳 | ⚠️ 先别做，收益主要是"仪式感" |
| **C · 在线服务** | 域名 + Caddy/Nginx + HTTPS + 密码 | 1–2 天 | 任何设备打开网址就能用，手机也行，什么都不用装 | ⚠️ 只有"要多设备"时才值得 |

### 先纠正一个误解：A / B / C 跟「几个人能用」没关系

很多人会以为"包成 exe 了大家就都能用"。不是的 —— 这两件事是分开的：

| | 你**怎么打开** | **谁能连上** |
|---|---|---|
| **A** 启动器 | 双击 → 自动建 SSH 隧道 → 独立窗口 | 只有**拿着服务器 SSH 密钥**的人（基本就是你）。把快捷方式发给别人没用 |
| **B** 安装包 | 双击 exe（壳里自带隧道 + 内嵌页面） | 同上。**把 exe 发给别人，别人也连不上** —— 他没有你的密钥，隧道建不起来 |
| **C** 在线服务 | 打开网址（电脑、手机都行） | **有地址 + 密码的人都能用** ← 只有这一条是"大家都能用" |

一句话：**"谁能用"取决于服务器怎么暴露（SSH 隧道 vs 公网域名），不取决于你用什么壳。**
壳只决定"你自己怎么打开"。

但——**别急着上 C**，真正拦住"多人用"的不是网络，是四件更硬的事：

1. **Easel 没有账号体系**：所有人共用一套数据、一个 `outputs/`、一份模型额度，谁改了什么查不到。
2. **一个会话同时只能一个人用**：openclaw 的会话被两个标签抢占会直接崩（这个坑本机已经踩过）。
   两个人同时干活 = 互相把对方顶掉。
3. **2G 内存 + 3Mbps**：一个 agent 干活就吃 700M+，两人并发必 OOM；图片预览的带宽也不够分。
4. **账号是你的**：别人在你的工作台里点"发布"，用的是你的小红书/抖音登录态。

**结论**：这台 2G 服务器 = **你一个人用**（可以多设备：电脑 + 手机，这算一个人）。
真要"大家都能用"，只有两条路：
- **每人一个独立实例**（一人一台机器 / 一个容器，各用各的 key 和账号）—— 成本按人头算；
- **把 Easel 改造成多用户系统**（加登录、加租户隔离、改会话模型）—— 那不是"封装"，是重写后端，不建议。

### A 的具体做法（推荐，先跑这个）

`启动工作台.ps1`：
```powershell
$IP = "<服务器IP>"
$chrome = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"

# 1) 后台建隧道（-N 只转发端口，不执行远程命令）
Start-Process ssh -ArgumentList '-N','-L','7860:127.0.0.1:7860',"root@$IP" -WindowStyle Hidden

# 2) 等隧道通（最多约 12 秒）
for ($i = 0; $i -lt 40; $i++) {
  if (Test-NetConnection 127.0.0.1 -Port 7860 -InformationLevel Quiet) { break }
  Start-Sleep -Milliseconds 300
}

# 3) 用"应用窗口"打开：无地址栏、无标签页，看着就是个软件
& $chrome --app=http://127.0.0.1:7860 --window-size=1440,900
```

做成桌面快捷方式（目标填 `powershell.exe -NoProfile -WindowStyle Hidden -File "<这个文件路径>"`），
换个图标，就和原生软件没区别了。

> **必须配免密登录**，否则每次双击都弹密码，"像软件"这件事就废了。
> 在本机 Git Bash 里：
> 1. `ssh-keygen -t ed25519 -f ~/.ssh/easel_server -N ""` 生成专用密钥
> 2. 把 `~/.ssh/easel_server.pub` 的内容追加到服务器 `~/.ssh/authorized_keys`
> 3. 本机 `~/.ssh/config` 加一段，以后直接 `ssh easel`：
>    ```
>    Host easel
>      HostName <服务器IP>
>      User root
>      IdentityFile ~/.ssh/easel_server
>      ServerAliveInterval 30
>    ```

### B 为什么建议缓一缓

- 壳里装的还是那个网页，**不解决任何实际问题**，只是把"打开浏览器"换成"打开自研窗口"。
- 多一条要维护的构建链（Electron 版本、签名、自动更新），而服务器 11-21 就到期。
- 真要做就选 **Tauri**（复用系统 WebView，包体 5–15MB），不选 Electron（100MB+）。

### C 在 2G 上跑得动吗？跑得动，但只适合"一个人多设备"

- **C 本身很轻**：Caddy 常驻 30–60MB，比 magpie 还小，2G 完全带得动。
- 真正吃内存的永远是 **agent 干活那一下**（700M+），跟加不加 Caddy 没关系。
- 所以：手机 + 电脑 + 平板轮流用 = 没问题；**两三个人同时在线干活 = 一定卡/OOM**。
- 带宽也一样：3Mbps 一个人看图够，两个人同时刷内容库就转圈。

### C 最大的好处：**你自己的电脑可以关着**

这一条经常被忽略，但很关键：

| | 用的时候，你的电脑 | 不用的时候 | 手机能用吗 |
|---|---|---|---|
| **A / B**（SSH 隧道） | **必须开着**（隧道是从你电脑建出去的，电脑关了隧道就断了） | 服务器照常在跑，但你打不开界面 | ❌ 手机建隧道很折腾 |
| **C**（公网网址） | **不用开**，任何设备打开网址就行 | 电脑随便关，服务器 24 小时自己跑 | ✅ 直接浏览器打开 |

也就是说：**A/B 是"你连上去"，C 是"它一直在那儿"。**
如果你想要的是"下班路上用手机看一眼、在别人电脑上也能接着干"，那只有 C 合适。

### C 做之前必须知道的风险

- Easel **自带没有登录**（`web/app.py` 绑 `0.0.0.0` 且无鉴权）→ 密码必须由 Caddy/Nginx 挡在前面。
- **国内机房 + 域名 + 80/443 = 要 ICP 备案**（个人备案通常 1–2 周）。不备案的话，云厂商可能直接拦。
  两个绕过的办法：
  - 用 **IP + 高端口**（如 `https://<IP>:8443`）—— 不用备案，但证书是自签的、浏览器每次要点"继续访问"；
  - 用 **Cloudflare Tunnel**（本机 PATH 里已有 `cloudflared`）把 7860 映射成一个 `https://xxx.trycloudflare.com`，
    不用备案、不用开防火墙端口，还能套 Cloudflare Access 做登录。缺点是免费隧道域名重启会变，回源带宽一般。
- 2G 小机器挂公网会被全网扫描、爆破。建议同时：装 `fail2ban`、只放行你自己的 IP、关掉 root 密码登录。
- 2G + 3Mbps 只够你一个人用，别想着分享给团队。

### 最重要的一条

这台服务器 **2026-11-21 到期**。封装是锦上添花，**先把"能不能稳定跑"验证完**
（§7 全绿 + 连续在线三天不崩），再谈封装。
不然一个月后壳还在、服务没了。
